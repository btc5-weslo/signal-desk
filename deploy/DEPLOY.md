# Demo deployment (signal-desk)

Web: Vercel (Next.js, `web/`). API: Render free plan (Docker, `deploy/api.Dockerfile`),
described in `/render.yaml`. No secrets live in this repo; set them in each dashboard.

## Data at runtime
The Parquet store is not committed. `deploy/bootstrap_data.py build` fills it during the
image build from data.binance.vision (public archive, SHA-256 checked): 5 USDT pairs x
15m/1h/4h/1d, recent months only, at least 200 closed bars per series or the build fails.
On every container start `deploy/bootstrap_data.py topup` adds the newest closed bars from
`ccxt:binanceus` in the background (the free disk is ephemeral and the service sleeps after
15 idle minutes). Bars are merged on open_time: binance_vision wins duplicates, each bar keeps
its own `source`, and `source_seam` marks the changeover. api.binance.com is never called
(it blocks US IPs). Both sources are shown in the app as not licensed.

## Render (API)
Blueprint from `render.yaml`: web service `signal-desk-api` (free) + Key Value
`signal-desk-kv` (free). No Postgres (the API uses its in-process repository) and no
worker (the free plan has none, and no market is QA-approved, so no signals are served).

| Var | Value |
| --- | --- |
| SIGNAL_ENV | `staging` (prod accepts only JWTs; there is no sign-in yet) |
| SIGNAL_USE_MOCK_DATA | `false` |
| SIGNAL_DATA_DIR | `/app/store` |
| SIGNAL_JWT_SECRET | generated by Render |
| SIGNAL_REDIS_URL, REDIS_URL | both from `signal-desk-kv` |
| SIGNAL_API_KEY | the demo key (backend accepts only its built-in `dev-key` outside prod; public) |
| SIGNAL_CORS_ORIGINS | the Vercel URL |
| SIGNAL_REFRESH_ON_START | optional, `0` disables the start-up top-up |

## Vercel (web)
Project root directory `web`, framework Next.js, "include files outside the root
directory" on (web imports `../shared` types).

| Var | Value |
| --- | --- |
| NEXT_PUBLIC_API_URL | `https://<render-service>.onrender.com` |
| SIGNAL_API_URL | same as above (server-only) |
| SIGNAL_API_KEY | the backend's demo key (server-only, never `NEXT_PUBLIC_`) |
| NEXT_PUBLIC_WS_URL | `wss://<render-service>.onrender.com` |
| NEXT_PUBLIC_USE_MOCK | `0` |

## Local check
    SIGNAL_ENV=staging backend/.venv/bin/python deploy/bootstrap_data.py build --out /tmp/store
    docker build -f deploy/api.Dockerfile -t signal-api .

## In-process scheduler (no worker on the free plan)
With `SIGNAL_INPROCESS_SCHEDULER=1` the API runs one cycle every
`SIGNAL_SCHEDULER_INTERVAL_SEC` (default 60): a sequential, small top-up of the newest
closed bars from `ccxt:binanceus` for every series (`app/pipeline/topup.py`), then the same
`run_pipeline` pass the arq cron uses. Cycles never overlap. The start-up top-up in
`start-api.sh` is skipped in this mode. Signals are still served only for QA-approved markets.
