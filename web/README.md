# Signal app — web (Next.js)

Dark-first, white-label dashboard for the trading signal app.
Stack: Next.js 15 (App Router) · TypeScript · Tailwind v4 · shadcn/ui (radix) · TradingView lightweight-charts · Vercel.

## Run

```bash
npm install
cp .env.example .env.local      # set NEXT_PUBLIC_API_URL
npm run dev                     # http://localhost:3000
NEXT_PUBLIC_USE_MOCK=1 npm run dev   # UI work without a backend (MOCK badges + banner)
npm run build && npm run lint && npm run typecheck && npm test
```

| Env var | Scope | Purpose |
|---|---|---|
| `NEXT_PUBLIC_API_URL` | public | Backend base, e.g. `http://127.0.0.1:8000`. Used to derive the WS URL and as the proxy default. |
| `NEXT_PUBLIC_WS_URL` | public | Optional WS base; defaults to the API URL with a `ws(s)` scheme |
| `NEXT_PUBLIC_USE_MOCK` | public | `1` = serve signals/strategies/candles/stream from `lib/mock/` (flagged MOCK everywhere) and use the default theme |
| `SIGNAL_API_URL` | **server-only** | Backend base for server-side calls (proxy, tenant config). Defaults to `NEXT_PUBLIC_API_URL`. |
| `SIGNAL_API_KEY` | **server-only** | Dev/service API key, sent as `X-API-Key` by the proxy when the user has no JWT. **Never** prefix with `NEXT_PUBLIC_`. |

Local dev against the real backend:

```bash
NEXT_PUBLIC_API_URL=http://127.0.0.1:8000 SIGNAL_API_KEY=dev-key npm run dev
```

### How requests are authenticated
- Browser REST calls go to the same-origin proxy `app/api/v1/[...path]` (allowlisted paths only), which forwards the
  user's `Authorization: Bearer <JWT>` or, if absent, adds the server-only `X-API-Key`. The key never reaches the browser.
- WebSocket: first-message auth `{type:"auth", token}` (what backend `_authenticate_ws` accepts) with the user's JWT, or (dev) a
  short-lived stream token minted server-side by `POST /api/stream-auth` → backend `POST /v1/stream/token` (`{token, expires_at}`)
  from `SIGNAL_API_KEY`. If that route is missing (404/405) the pill shows "Sign in required" and no socket is opened.
  "Live" is shown only after a message arrives or the socket survives 1.5 s after the auth frame; close code 4401 → "Sign in required".
- **Data scoping comes only from the JWT / API key.** The request host is used solely to pick branding
  (`GET /v1/tenant/config`, sent with `X-Forwarded-Host` and no credentials). The proxy does not forward Host or
  `X-Forwarded-Host` on data requests.

## Layout

```
app/                     routes: / (dashboard), /signals, /signals/[id], /markets/[symbol]?tf=, /strategies, /strategies/[id], /settings, /welcome; api/v1/[...path] proxy, api/stream-auth
components/shell/        app shell (collapsible sidebar, top bar, mobile sheet + bottom nav), WS status pill, tenant + stream providers
components/signals/      feed (cards/table + filters), signal detail, candlestick chart with levels + risk/reward zones
components/strategies/   strategy list/detail, metrics, review banner (QA flags), provenance, equity curve, trades table
components/common/       badges (side/status/MOCK/validation), confidence meter/gauge, disclaimers, empty states
lib/types/signal.ts      the ONE contract file: re-exports generated types from ../shared/ts + @proposed fields
lib/api/client.ts        typed REST client (JWT bearer). /v1/signals + /v1/strategies return {items,next_cursor} (?cursor=); /v1/candles bare array; /v1/backtests/{run_id}; /v1/health
hooks/use-signal-stream.ts  WS /v1/stream/signals, first-message auth {type:"auth",token} on open (server timeout 5s), exponential backoff + jitter, 4401 => "Sign in required"
lib/mock/                ALL mock data (only loaded when NEXT_PUBLIC_USE_MOCK=1). No mock backtests, ever.
lib/disclaimers.ts       QA-approved disclaimer texts (qa/DISCLAIMERS.md); tenants can append lines only
lib/tenant.ts            TenantTheme, neutral default theme (placeholder brand), config→theme mapping, CSS vars
lib/tenant-server.ts     server-side GET /v1/tenant/config (by host, revalidate 300s) with fallback to the default
```

## Contracts

Types come from `/shared/ts/index.ts` (generated by Backend from `/shared/*.schema.json`) via the
`@shared/*` tsconfig path (`experimental.externalDir` in `next.config.ts`). `lib/types/signal.ts` is
the only file that imports them; it adds UI narrowing (`normalizeSignal`) and fields marked
`@proposed` (`validation_status`, `validation_by_market`) that the team still needs to adopt.

**Vercel:** set Root Directory to `web/` and keep "Include files outside the root directory" enabled so `../shared` is available at build.

## Performance-data rules (enforced in UI)

- Strategy performance renders **only** from `/v1/backtests/{run_id}` JSON. The API serves QA-approved runs only, so any returned report counts as approved; the UI does not read `qa_approved`/`qa_status`. No run → "No validated backtest yet".
- Reports are per `strategy_id + version + symbol + timeframe`, plus a strategy **summary** (`symbol`/`timeframe` null, `flags` = union). Strategy cards use the summary (`latest_run_id`). Strategy detail lists per-market reports from `GET /v1/backtests?strategy_id=&version=` (`{items:[{symbol,timeframe,run_id,flags,approved}]}`), each with its own validation state; the full report is fetched via `/v1/backtests/{run_id}` and metrics are shown **only** for markets that are `approved` with empty `flags`. `?run=<run_id>` opens one.
- Any entry in `flags` → **Under review**: headline metrics, equity curve and trades table are hidden; flags are listed with friendly labels (`low_oos_trades`, `sharpe_gt_3`, `win_rate_gt_75`, `insufficient_oos_history`, `data_quality_warning`, `metric_recompute_mismatch`); unknown flags show raw.
- `insufficient_oos_history` (or `validation_status: "insufficient_oos"`) → amber "Unvalidated: insufficient out-of-sample history".
- Provenance (`run_id`, `data_hash`, fees/slippage bps, period, windows, trade count) is always visible.
- Every performance figure carries the approved "Hypothetical backtested results…" note.
- Confidence: shown as a percentage **only** when `confidence_calibrated` is true (tooltip links to `calibration_run_id`); otherwise as a 0–1 "Model score" (e.g. `0.68`), never with `%`.
- `/v1/candles` 404/empty → "No candle data available". Candles are never synthesized outside mock mode. Bars are sorted/de-duplicated; gaps (dropped zero-volume bars, closed sessions) are left as gaps, never interpolated. Every chart shows a `Data: <source>` caption and an amber "Provisional data, not for live trading" note when any bar has no `source` or an unlicensed one. `binance_vision`, `yfinance` and any `ccxt:*` source are hard-coded as never licensed. Otherwise a source is licensed only if it's in the platform's read-only `licensed_data_sources` from `GET /v1/tenant/config` (empty today). That list is read only there (`lib/data-policy-server.ts` → `DataPolicyProvider`) and is deliberately not part of the tenant theme, so local defaults, env, previews or tenant overrides can't set it. On failure or in mock mode it's empty. Logic: `lib/data-provenance.ts` (tested). If bars carry several sources, the caption lists every one exactly as reported (e.g. `Data: binance_vision, ccxt:binanceus`).
- Freshness: charts show an amber "Data delayed: last bar <age>" notice when the newest bar's close (open + 1 interval) is more than 2 intervals behind now (15m/1h/4h/1d). Crypto uses wall-clock time. FX counts only open hours (closed Fri 22:00 to Sun 22:00 UTC) and US equities only Mon–Fri 09:30–16:00 New York (a daily bar = one 390-minute session), so weekends and overnight closes aren't flagged. Exchange holidays and half days aren't modelled, so the session right after one can show as delayed briefly. Anything over 10 days behind is always delayed. Logic: `lib/data-freshness.ts` (tested, with an injected `now`).
- Strategy text (`lib/strategy-text.ts`, tested): `description`, `hypothesis` and `hypothesis_id` pass the same banned-claims guard as tenant text; anything that fails, or is null or empty, is hidden. The description is shown only when it differs from the name (case- and whitespace-insensitive). `hypothesis_id`, or for now a bare-id `hypothesis` like `H1`, renders as a small tag next to the version. Only a full-sentence hypothesis gets the "Hypothesis" section.
- `tests/disclaimers-drift.test.ts` fails if `lib/disclaimers.ts` drifts from `../qa/DISCLAIMERS.md`, or if that file is missing.
- Strategy pages always show the per-market table. With no backtests in `GET /v1/backtests` it shows one "Not yet validated" row with no numbers; if the list fails to load it says so instead.
- `data_quality_warning` → amber "Data quality" chip on the market row / report.
- No product cost, plan tiers or paid gating anywhere in the UI. Verify with `python ../qa/audits/no_price_scan.py web`.

## White-label theming

**Branding is data, not code.** The root layout calls `getTenantForRequest()` (`lib/tenant-server.ts`), which fetches
`GET /v1/tenant/config` server-side (backend resolves the tenant by host; we forward the browser host as `X-Forwarded-Host`),
cached with `revalidate: 300`. The response `{tenant_id, name, logo_url, colors{}, extra_disclaimers[], tagline?}` is mapped to a
`TenantTheme` and written as CSS variables on `<html>` (no flash). On any failure, or in mock mode, the neutral
`defaultTenant` in `lib/tenant.ts` is used.

- **Trusted proxy requirement:** the backend honors `X-Forwarded-Host` only from allowlisted proxies. Add the Next.js
  server's origin (the Vercel deployment / custom domain egress, and `localhost` for dev) to the backend's trusted-proxy
  allowlist, otherwise every tenant resolves to the default theme.
- **Name, logo and tagline** render only from the tenant object (`tagline` from config when present, else the default). The placeholder brand ("Signal Desk", `/logo.svg`,
  "Multi-market trading signals") exists only in `defaultTenant` in `lib/tenant.ts` — a one-line swap each.
- Colors: hex only (`bg, surface, surface2, border, text, muted, accent, accentText, long, short, warning`; snake_case aliases accepted). Invalid values fall back to the default token.
- Logo: `https://` or site-relative URLs only.
- `extra_disclaimers` are **appended** after the QA defaults (footer + onboarding). Tenants cannot remove or replace the defaults.
- **Banned-claims guard** (`lib/tenant-guard.ts`, tested in `tests/tenant-guard.test.ts`): tenant name, tagline and extra disclaimer lines are rejected (falling back to the default / dropped) if they contain product-cost copy (patterns ported from `qa/audits/no_price_scan.py`), banned claims (guaranteed, validated, risk-free, sure win, can't lose, 100%, NN% accuracy/win) or any currency amount.

Design tokens live in `app/globals.css` (`--bg --surface --surface-2 --line --text --text-muted --brand --brand-text --long --short --warning --radius`);
shadcn's semantic variables derive from them, so every component re-themes. Settings → "White-label theme preview" shows the active theme next to an example palette.
